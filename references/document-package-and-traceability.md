## 正式交付契约

用户要求编写、更新、拆分、分配或同步开发文档时，把仓库内可维护文件作为正式产物。聊天内容用于澄清、审批和交付导航，不得用一段汇总文字替代已批准的文档写入。

遵循以下优先级：

1. 更新仓库已有权威文档和索引。
2. 在既有文档体系中补齐缺失文件。
3. 没有既有约定时，使用本引用的默认文档包结构。
4. 只有用户明确要求仅在聊天中输出，或当前没有可写工作区时，才使用聊天型交付例外。

Level 2-3 若只有聊天总结、一个未分区的大段文本或无法从索引发现的散落文件，不得宣称文档交付完成。

## 文档颗粒度

一份文档只承担一个主要权威职责。出现以下任一情况时拆分为独立文件：

- 面向不同受众或维护角色。
- 具有不同审批范围、状态或维护周期。
- 会被不同下游文档、任务或系统独立引用。
- 需求、架构、数据、API、验证或任务信息需要独立演进。

Level 1 的单一局部变更可以保留在一份结构化文档中。Level 2-3 不得为了减少文件数量，把多个独立职责重新合并为“大而全”的方案文档。

仓库若明确规定使用单文件规范，应遵循现有权威结构，但必须为每个独立主题提供稳定标题、锚点、ID 和索引入口，使其可以单独引用和维护。

## Level 1-3 产物形态

### Level 1

- 一份结构化变更说明。
- 文档内使用明确章节、列表、表格和稳定任务编号。
- 不允许用无标题的连续段落替代范围、影响、任务和验收信息。

### Level 2

- 一个权威包级索引。
- 按职责拆分的适用需求、设计、影响/路线图和验证文档。
- 可独立分配的任务卡及任务索引。
- 不生成与本任务无关的空文件。

### Level 3

- 一个权威包级索引。
- 完整适用的需求、流程、架构、数据、API、影响、路线图和验证文档链。
- 跨文档决策使用独立决策记录。
- 每个可独立分配的任务使用独立任务卡，并由任务索引统一维护状态。

## 默认文档包结构

优先使用仓库已有结构。没有约定时使用：

```text
docs/
  plans/
    <level-1-task>.md
  planning/
    <level-2-or-3-task>/
      index.md
      requirements.md
      flows.md
      architecture.md
      data-model.md
      api-contract.md
      impact-and-roadmap.md
      verification-plan.md
      decisions/
        DEC-001-<slug>.md
      tasks/
        index.md
        TASK-001-<slug>.md
```

只创建适用文件。现有权威文档位于其他目录时，索引应指向并更新该文档，不复制出平行版本。

## 文档索引

Level 2-3 必须有一个权威索引；可复用仓库现有索引，无法承载本任务时才创建局部 `index.md`。索引至少包含：

```markdown
# [任务] 文档包

## 文档清单
| 文档 ID | 路径 | 类型 | 权威范围 | 状态 | 负责人 | 上游依赖 | 替代关系 |
|---|---|---|---|---|---|---|---|

## 任务状态
| 任务 ID | 任务卡 | 推荐角色 | 负责人 | Wave | 依赖 | 状态 |
|---|---|---|---|---:|---|---|

## 追踪矩阵
| 需求 | 决策/设计 | 实施任务 | 验证项 | 状态 |
|---|---|---|---|---|

## 未决问题
- 仅记录不阻塞当前文档正确性的执行阶段待验证项。
```

## 通用元数据与编号

优先遵循仓库已有 front matter、编号和状态规范。没有约定时，Level 2-3 文档记录：

```markdown
- 文档 ID：DOC-001
- 状态：Draft / Proposed / Approved / Superseded / Archived
- 权威范围：
- 负责人：具体人员或 Unassigned
- 推荐维护角色：
- 来源需求：
- 上游文档：
- 下游文档或任务：
- 替代/被替代：
- 最后更新：YYYY-MM-DD
```

默认编号在当前文档包内唯一：`DOC-001`、`REQ-001`、`DEC-001`、`TASK-001`、`RISK-001`、`CHK-001`。不额外维护容易失真的人工版本号；历史版本由仓库现有版本控制保留。

## 聊天型交付例外

只有用户明确要求仅在聊天中输出，或当前没有可写工作区时使用。此时：

- 按独立文档块输出，每块有文档 ID、标题、状态和明确边界。
- 保留索引、任务状态和追踪矩阵。
- 明确标注“未持久化，不是可维护的仓库文档”。
- 不得用一段连续文字合并多个文档职责。

## 最终交付格式

文档写入后，聊天回复只提供交付导航，不重复粘贴全部正文：

```markdown
## 文档交付
| 文档 | 状态 | 职责 |
|---|---|---|

## 任务交付
- 任务总数：
- 已分配：
- Unassigned：
- 可开始 Wave：

## 验证
- 索引与链接：
- ID 唯一性：
- 追踪完整性：

## 未决问题
```
