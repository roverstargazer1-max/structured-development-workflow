# Level 1-3 文档深度

## 判定维度

只在通过文档就绪检查后分级。信息不足不是 Level 3 的替代判据；先返回 `CLARIFY` 并等待真实背景补全。

综合范围、角色数量、模块数量、产品影响、数据/安全风险、外部契约、可逆性、迁移需求和不确定性分级。任一高风险维度可提升等级，不因预估代码量小而降低认证、支付、权限、隐私或数据迁移任务的等级。

| 维度 | Level 1 | Level 2 | Level 3 |
|---|---|---|---|
| 范围 | 单一局部、目标明确 | 单模块或相邻模块 | 跨模块、跨服务或新项目 |
| 角色/流程 | 单一角色和路径 | 多角色或多个关键分支 | 核心流程、复杂权限或多系统协作 |
| 数据/契约 | 无变更 | 兼容性新增或普通字段变化 | 重大迁移、隐私数据或破坏性契约 |
| 执行阶段不确定性 | 低 | 有少量不阻塞文档正确性的待验证项 | 产品意图已确认，但执行投入、迁移或风险较大 |

## Level 1：单份变更说明

创建或更新一份紧凑文档，至少包含：

1. 背景、目标和非目标。
2. 当前事实和约束。
3. 直接影响与不受影响范围。
4. 任务清单及推荐角色。
5. 验收标准和测试要求。
6. 文档新增、更新、归档或删除清单。

不强制生成独立 PRD、架构、数据模型或 API 文档。单文件仍必须使用明确章节、表格和稳定任务编号，不得退化为连续长段总结。没有仓库约定时，使用 `docs/plans/<task>.md`。

## Level 2：轻量文档包

必须形成一个可发现的权威索引，并按职责形成适用文件：

- 轻量 PRD 或需求摘要。
- 产品、页面、调用或异常流程。
- 技术设计及适用的数据/API 变化说明。
- 影响分析和实施路线图。
- 独立任务卡、任务索引、依赖、角色建议和执行交接包。
- 测试与验收计划。

只生成真正相关的产物，不创建空文件。不同受众、维护角色、审批范围或生命周期的内容必须分文件。没有仓库约定时，使用 `docs/planning/<task>/`。

## Level 3：完整适用文档链

形成：

`需求澄清 → 一页 PRD → 产品/异常流程 → 页面与交互草图（仅 UI）→ 技术架构 → 数据模型（仅数据）→ API 契约（仅接口）→ 影响与风险 → 实施路线图 → 任务分配 → 测试与验收计划 → 执行交接包`

Level 3 必须包含包级索引；每个适用设计职责使用独立文件，跨文档决策使用独立决策记录，每个可独立分配的任务使用独立任务卡。“完整适用”不表示制造无关文档。纯后端任务不创建页面草图；没有持久化变化时不创建数据迁移设计；没有接口时不创建 API 契约。

## 升降级规则

- 在文档变更计划中说明等级、依据、采用和跳过的产物。
- 证据不足以确认范围、风险或必要产物时停止分级并返回澄清；不得以较高等级掩盖信息缺口。
- 规划中发现范围、架构、数据、API、安全或验收标准实质扩大时，重新分级并更新文档变更计划。
- 外部执行结果扩大范围时，仅更新影响、路线图和任务状态；不得接管代码实现。
