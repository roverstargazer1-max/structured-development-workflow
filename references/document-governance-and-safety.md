## 允许和禁止的操作

批准后允许：

- 创建、更新和重组 Markdown、MDX、AsciiDoc、RST、纯文本等开发文档。
- 更新 README、贡献指南、架构、运维、部署说明等人类可读文档。
- 在单独批准后维护 OpenAPI、Proto、JSON/YAML Schema 等机器可读契约规范。
- 更新文档索引、任务状态、决策记录和外部执行结果。
- 运行文档、链接、图表、语法和静态契约校验。

始终禁止本 Skill 执行：

- 修改业务源代码、测试、构建配置、依赖清单、锁文件、ORM 模型、迁移脚本或实现性配置。
- 安装/升级依赖，运行应用测试、构建、Lint、类型检查、迁移、代码生成或部署命令。
- `git add`、提交、推送、建分支、创建 PR、合并、打标签、发布或改写历史。
- 启动、委派或监督开发 Agent。

若某文件同时是文档和运行时配置，默认视为实现文件，只提供建议；除非它属于明确批准的机器契约规范。

## 文档盘点

在提出变更前记录：

```markdown
| 文档 ID | 文档 | 类型 | 当前状态 | 权威范围 | 索引入口 | 入站引用 | 与本任务关系 | 建议操作 |
|---|---|---|---|---|---|---|---|---|
```

检查仓库文档目录、README/索引、局部 `AGENTS.md`、链接、同名主题和版本标记。识别：

- 当前权威来源。
- 重复、冲突或过时内容。
- 缺失的文档环节。
- 历史/审计价值和归档要求。
- 机器契约是否被代码生成或外部消费者使用。

## 变更审批

任何写入前输出文档变更计划。批准边界按操作区分：

| 操作 | 所需批准 |
|---|---|
| 新增或普通更新人类可读文档 | 批准文档变更计划 |
| 移动、重命名、合并或归档 | 计划中明确路径和引用修复并获批准 |
| 修改机器可读契约 | 针对契约、兼容影响和消费者的单独批准 |
| 永久删除 | 引用检查和归档/替代方案后单独批准 |

用户批准某份文档不等于批准其他文件、契约变化或删除。计划范围发生实质变化时停止相关写入并重新批准。

## 契约规范门禁

修改 OpenAPI、Proto、Schema 前：

1. 确认权威文件和消费者。
2. 说明新增、兼容或破坏性变化。
3. 说明版本、迁移和回滚设计。
4. 列出执行者后续需要完成的代码、测试和生成任务。
5. 获得对具体文件和范围的单独批准。
6. 只编辑契约文档并运行静态语法/契约校验。
7. 禁止代码生成、消费者更新和应用测试。

若无法确认文件是否驱动运行时或代码生成，先按机器契约处理并请求批准。

## 合并、归档与删除

默认优先级：更新权威文档 → 合并重复内容 → 标记 `Superseded` → 移至仓库既有归档区 → 永久删除。

归档或拟删除前：

- 搜索文档、README、索引、Issue 模板和配置中的入站引用。
- 指定替代文档和迁移说明。
- 保留必要的历史、决策和审计信息。
- 修复经批准范围内的文档引用。
- 对无法确认的外部引用披露风险。

没有既有归档约定时，优先在原文档标记 `Superseded` 并链接替代项，不擅自创建新的全局归档体系。永久删除必须获得单独明确授权。

## 只读 Git 和环境安全

允许根据需要使用：

```bash
git status --short
git diff --stat
git diff
git log
git show
git ls-files
```

这些命令只用于识别现状、历史和文档影响。不得暂存、提交、切换/创建分支、清理、重置、恢复、stash、推送或修改远程状态。

不要安装文档工具。优先使用仓库已经提供的文档或契约校验器；没有可用工具时执行静态检查并披露限制。

## 完成检查

- [ ] 实际写入只包含已批准的文档和契约范围。
- [ ] 没有修改源代码、测试、配置、依赖、迁移或生成物。
- [ ] 文档包清单中的新增或更新项均已落盘，未批准项未写入。
- [ ] Level 2-3 有权威索引，所有非归档文档和任务卡都可从索引发现。
- [ ] 文档与任务 ID 唯一，权威范围、状态、负责人、上下游和替代关系可追踪。
- [ ] 每个需求、决策、风险、任务和验证项的适用关系已经闭合。
- [ ] 每个可独立分配的 Level 2-3 任务都有独立任务卡或稳定锚点。
- [ ] 没有用聊天总结或单个未分责大文件替代 Level 2-3 文档包。
- [ ] 移动、合并和归档后的引用已检查。
- [ ] 契约变化有单独批准和兼容说明，未运行代码生成。
- [ ] 没有执行任何 Git 写操作或远程操作。
- [ ] 交付说明明确区分文档完成与功能实现。
